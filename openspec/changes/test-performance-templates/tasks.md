- Implementation starts only after a subsequent user request to apply this plan. Preserve the unrelated user edit in `docker-compose.postgresql.yml` and exclude it from task commits.
- Keep this work on its dedicated branch. Setup PR #1 must be corrected, green and merged before creating a focused PR from this branch to main; its merge also needs explicit user approval. Record any upstream merge used to reconcile the branch; do not squash/rebase existing task commits.
- When every tracked task and required check passes, archive this tooling-only change with no product-spec sync and inspect/commit the archive in a separate lifecycle commit.
- Publish the branch and create/attach the PR targeting main after archive. Include task commits, the three-mode performance comparison, isolation evidence and actual coverage. Require automatic full CI on the final archived PR revision; failed or missing gates block merge.
- Wait for explicit user approval of the concrete PR before merging. Use a merge commit preserving each task commit; never squash or rebase merge. Local instructions do not claim remote branch protection or change GitHub administrative settings.
